# หัวใคร ใครรู้? — v0.3

เว็บเกม multiplayer สำหรับเล่นเกมทายตัวละครบนหัวกับเพื่อน สร้างด้วย React, Node.js, Express และ Socket.IO

## ฟอนต์

ใช้ **Arabica** จากไฟล์ที่เจ้าของโปรเจกต์ให้มา ครอบคลุมภาษาไทย/อังกฤษ ทั้งข้อความ ปุ่ม ช่องกรอก รหัสห้อง และตัวเลขเวลา ไฟล์ Regular และ Italic อยู่ใน `client/src/assets/fonts/` และถูกนำไปด้วยเมื่อ build จึงไม่ต้องติดตั้งฟอนต์บนเครื่องผู้เล่นหรือโหลดจากบริการภายนอก

ใช้ `font-display: swap` พร้อมฟอนต์สำรองระหว่างโหลด และให้เบราว์เซอร์จำลองตัวหนาเพราะชุดนี้ไม่มีไฟล์ Bold รายละเอียดแหล่งที่มาอยู่ใน `client/src/assets/fonts/README.md` โปรดตรวจสิทธิ์การฝังและแจกจ่ายฟอนต์บนเว็บก่อนเผยแพร่ เพราะ ZIP ที่ให้มาไม่มีเอกสารอนุญาตแยก

## กติกาใหม่ใน v0.3

1. โฮสต์เลือก **1–10 รอบ** ตอนสร้างห้อง (หน้าเว็บเลือก 3 รอบไว้ให้) จำนวนรอบคงที่ตลอดเกม หากต้องการเปลี่ยนให้สร้างห้องใหม่
2. ผู้เล่นทุกคนส่งชื่อและรูป **หนึ่งตัวละครต่อรอบ** ให้ครบล่วงหน้า เช่น 3 รอบ = คนละ 3 ตัว กดยืนยันแต่ละช่องแยกกัน แก้ไขได้ก่อนเริ่มเกม ตัวละครที่ยืนยันแล้วจะกลับมาเมื่อ refresh; ข้อมูลที่ยังไม่กดยืนยันจะไม่ถูกบันทึก
3. เริ่มได้เมื่อมีอย่างน้อย 2 คน ทุกคนออนไลน์และส่งครบ เซิร์ฟเวอร์สุ่มแยกแต่ละรอบด้วย derangement: ไม่ได้ของตัวเอง และตัวละครแต่ละช่องถูกใช้เพียงรอบเดียว
4. แต่ละตา **15 วินาที** คิวเรียงตามการเข้าห้อง รอบต่อไปหมุนคนเริ่ม ผู้เล่นเห็นคำตอบของคนอื่น แต่ของตัวเองเป็น `???` รูปแสดงเต็มสัดส่วน
5. เฉพาะเจ้าของตากด **กดตอบ** ได้ เวลาหยุดระหว่างเพื่อนทุกคนโหวต **ทายถูก/ทายผิด** พูดคำตอบผ่าน Discord, LINE หรือโปรแกรมภายนอกเหมือนเดิม
6. **ถูกทุกเสียง:** ได้คะแนนตามอันดับที่ทายถูก เปิดเผยตัวละครของตัวเอง และข้ามคิวตัวเองจนจบรอบ แต่ยังต้องช่วยโหวตให้เพื่อน
7. คะแนน = จำนวนผู้เล่นตอนเริ่มรอบ − อันดับ เช่น **4 คนได้ 3, 2, 1, 0 แต้ม**; 3 คนได้ 2, 1, 0; 2 คนได้ 1, 0 เมื่อเหลือคนที่ยังไม่ทายถูกคนสุดท้าย ให้ 0 แต้มและจบรอบทันที ไม่ต้องโหวตคนสุดท้าย
8. **ผิดทุกเสียง:** เล่นตาเดิมต่อด้วยเวลาที่เหลือ **เสียงไม่ตรงกัน:** แสดง “ผลไม่เป็นเอกฉันท์” ล้างเฉพาะบัตรโหวตแล้วโหวตใหม่ ไม่ล้างคะแนนสะสม
9. จบรอบเปิดเผยตัวละครทุกคน พักดูผล **6 วินาที** แล้วเริ่มรอบถัดไปอัตโนมัติด้วยตัวละครที่ส่งไว้ คำตอบของตัวเองจะถูกซ่อนใหม่
10. ครบทุกรอบแสดงตารางคะแนนรายรอบ คะแนนรวมและผู้ชนะ คะแนนสูงสุดเท่ากันเป็น **ผู้ชนะร่วม** โฮสต์กด **เริ่มเกมใหม่** และยืนยันเพื่อล้างคะแนน/ตัวละคร กลับ lobby โดยใช้จำนวนรอบเดิม

เวลา การเปลี่ยนตา/รอบ คะแนนและผลโหวตควบคุมจากเซิร์ฟเวอร์ Refresh ไม่เพิ่มเวลา ไม่ล้างคะแนนหรือโหวตที่ส่งแล้ว ใช้ session token ใน localStorage เพื่อกลับเป็นผู้เล่นเดิม เซิร์ฟเวอร์ไม่ส่งคำตอบของตัวเองที่ยังทายไม่ถูกหรือคำตอบของรอบอนาคตไปยัง client

ถ้าผู้เล่นหลุดชั่วคราวจะยังมีที่นั่งเดิมและต้องกลับมาโหวต ไม่ตัดสินคะแนนแทน หากกดออกจากห้องจริงจะข้ามคิวหรือเปิดโหวตใหม่ตามสถานะ คะแนนที่ได้แล้วคงอยู่ในตาราง (ระบุว่าออกจากห้อง) รอบที่ยังไม่ได้แต้มจะได้ 0 เมื่อจบรอบ รอบถัดไปคิดคะแนนตามจำนวนคนที่เหลือ หากเหลือน้อยกว่า 2 คนก่อนจบเกมจะยกเลิกเกม กลับ lobby และล้างคะแนน/ตัวละคร

### อัปเดตเครื่องที่รันเกมอยู่

```bash
npm test
npm run build
npm start
```

หากมีเซิร์ฟเวอร์เวอร์ชันเก่าทำงานอยู่ ให้หยุดด้วย Ctrl+C ก่อน `npm start` ใหม่ และ refresh หน้าผู้เล่นทั้งหมด ห้องเก่าจะหายเมื่อรีสตาร์ต สำหรับโฮสต์ออนไลน์ให้ใช้ Build Command `npm ci --include=dev && npm run build` และ Start Command `npm start` เหมือนเดิม

## ความสามารถ

- สร้างห้องและเข้าร่วมด้วยรหัส 6 ตัว
- Lobby แสดงผู้เล่นและสถานะความพร้อมแบบ realtime
- เลือก 1–10 รอบ แต่ละคนส่งชื่อตัวละครพร้อมรูป PNG, JPG, WEBP หรือ GIF ให้ครบทุกรอบ (ไฟล์ละไม่เกิน 3 MB)
- Host เริ่มเกมได้เมื่อมีอย่างน้อย 2 คน ทุกคนออนไลน์ และส่งตัวละครครบ
- สุ่มตัวละครแบบ derangement รับประกันว่าไม่มีใครได้ตัวละครที่ตัวเองส่ง
- ระหว่างเล่นเห็นคำตอบของเพื่อนทุกคน แต่คำตอบของตัวเองถูกซ่อนเป็น `???`
- Refresh หรืออินเทอร์เน็ตหลุดชั่วคราวแล้วกลับเข้าห้องเดิมได้ด้วย session ใน `localStorage`
- สะสมคะแนนหลายรอบ แสดงตารางอันดับและผู้ชนะรวม; Host เริ่มเกมใหม่ได้โดยไม่ต้องสร้างห้องใหม่
- Responsive ใช้งานได้ทั้งคอมพิวเตอร์และมือถือ

> ห้องและรูปภาพถูกเก็บในหน่วยความจำของ server เท่านั้น เมื่อปิด server ข้อมูลจะหาย เหมาะสำหรับ local development และวงเล่นขนาดเล็ก

## ติดตั้งและรันสำหรับพัฒนา

จากโฟลเดอร์โปรเจกต์ รัน:

```bash
npm install
npm run dev
```

จากนั้นเปิด [http://localhost:5173](http://localhost:5173)

- React/Vite: `http://localhost:5173`
- Node.js/Socket.IO: `http://localhost:3001`
- ตรวจสถานะ server: `http://localhost:3001/health`

ลองเล่นคนเดียวหลายหน้าต่างได้ด้วย Browser Profile หรือ Incognito ที่แยก `localStorage` กัน หากเปิดสองแท็บปกติ session เดียวกัน แท็บล่าสุดจะรับช่วงผู้เล่นคนนั้นต่อ

## ทดสอบ

```bash
npm test
npm run build
```

ชุดทดสอบครอบคลุมการส่งตัวละครหลายรอบ/ความพร้อม, validation จำนวนรอบและช่องตัวละคร, สุ่มไม่ซ้ำช่องและไม่รับของตัวเอง, ไม่เปิดเผยคำตอบอนาคต, คิว 15 วินาที/ข้ามคนที่ทายถูก, หยุดและคืนเวลา, โหวตถูก/ผิด/ไม่เป็นเอกฉันท์, ปฏิเสธโหวตซ้ำ/โหวตเก่า, คะแนน 3–2–1–0, หลายขนาดห้อง, คะแนนเสมอ, reconnect, ออกจากห้อง และ reset โดยมีทั้ง unit tests และ Socket.IO จริง 4 ผู้เล่นครบ 3 รอบ

หากสภาพแวดล้อมจำกัดสิทธิ์ทำให้ Vite โหลด config ผ่าน esbuild ไม่ได้ สามารถใช้ `npm run build -w client -- --configLoader native` กับ Node.js รุ่นที่รองรับได้ (ทดสอบด้วย Node.js 24)

```bash
npm run build

```

เปิด [http://localhost:3001](http://localhost:3001) โดย Express จะให้บริการไฟล์ frontend ที่ build แล้ว

## Environment variables

คัดลอก `.env.example` เป็น `.env` หรือกำหนดค่าจาก shell ก่อนรัน:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3001` | พอร์ตของ Express และ Socket.IO |
| `CLIENT_ORIGIN` | `http://localhost:5173` | Origin ที่อนุญาตระหว่างพัฒนา |

Node.js ไม่อ่านไฟล์ `.env` อัตโนมัติในโปรเจกต์นี้ หากต้องการใช้ไฟล์โดยตรงให้รัน `node --env-file=.env server/src/index.js` หรือกำหนดตัวแปรผ่านระบบที่ใช้ deploy

## โครงสร้างโปรเจกต์

```text
guess-who-party/
├─ client/                 React + Vite
│  └─ src/
│     ├─ App.jsx           หน้าสร้าง/เข้าห้อง, จำนวนรอบ และส่งตัวละคร
│     ├─ Game.jsx          คิว, โหวต, คะแนนสะสมและสรุปผู้ชนะ
│     └─ styles.css        responsive UI ทั้งหมด
├─ server/                 Express + Socket.IO
│  ├─ src/
│  │  ├─ app.js            room lifecycle และ socket events
│  │  ├─ game.js           room code, derangement และ safe state
│  │  ├─ round.js          คิว, timer, โหวต, คะแนนและเปลี่ยนรอบ
│  │  └─ index.js          จุดเริ่ม server
│  └─ test/               unit + Socket.IO integration tests
└─ package.json            workspace scripts
```
